## 总问题

数据稀缺时，TinyTL 应该怎样配置才能在精度、内存和计算之间取得最好的平衡？配置包括三项：适配哪些层、batch 取多大、分类头怎样初始化。

能不能在 TinyTL 框架里低成本地借用 TinyTrain 的两个思路：按任务选层、用 imprinting 初始化分类头？同时，要澄清两篇论文对小 batch 的矛盾说法。

## 一、所有实验共用的设置

- **模型**：ProxylessNAS-Mobile，用 TinyTL 发布的 lite residual 权重（ws+gn），输入 224 px，冻结权重做 8-bit 量化。
- **训练**：上游配方。Adam + 余弦学习率，50 轮，标签平滑 0.7，batch 8。直接测最后一轮，不按 val 挑 checkpoint。
- **数据**：每类取 k 张训练图。
  - Flowers102 是近域：train 每类 10 张，test 6,149 张。
  - FGVC-Aircraft 是远域：100 个机型，train 每类约 33 张，test 3,333 张。
- **配对**：同一种子下，各截断方式（arm）的训练图、分类头初始化、量化权重和数据顺序都相同。
- **统计**：
  - 效应 d = arm − LB，单位是百分点，按种子配对。
  - 用双侧 93% t 区间 [L, U]，边界为 2 个点。
  - 四个标签：retains（L > −2）、inferior by more than the margin（U < −2）、size unresolved、inconclusive。
  - Holm（单侧 0.035）只校正 retains 结论。
- **事后指标**（不是预先登记的，对应故事的目的）：
  - 保留率 R = (arm − last) / (LB − last)；
  - 训练−测试差距；
  - 各内存预算下的最好配置；
  - 选层可提升空间：每个种子挑最好的 arm，减去最好的固定 arm，是任何按任务选层规则能多拿到的上限。

## 三、各实验的内容和结果

### E0 复现与测量

- **目的**：先确认基线是对的，再弄清内存到底花在哪里。故事 ② 说内存的大头是激活值，TinyTL 论文报告 37 MB，要验证这个数字在实际训练里是否成立。
- **做什么**：
  - 在全量 Flowers102 上复现 TinyTL，224 px。
  - 每个 arm 在 batch 8 和 batch 1 下，用三种口径测内存：profiler、理想实现的下限、PyTorch 实测峰值。
  - 再测每张图的前向和反向 MACs，以及空闲 GPU 上每一步的时间。
- **结果**：
  - 复现精度 95.20%，论文是 95.5%。
  - batch 8 时 LB 的 profiler 是 37.1 MB，PyTorch 实测是 557.2 MiB，理想实现下限是 246 MiB。差距来自 GroupNorm：它的输入必须保存，单这一项在 PyTorch 里就占 172–175 MiB。
  - 真正的内存杠杆是两个：
    - 反传深度：LB 对 T3/T4/last，实测省 3.3×、5.3×、8.3×；
    - batch：b8 对 b1，实测省 4.6×。
  - profiler 完全看不到深度这个杠杆。
- **结论**：后面所有内存比较都用 PyTorch 实测值。

### E1 k=5 截断深度 × 数据集（预先登记的主实验）

- **目的**：对应故事 ⑧"固定只训练后几层"。问题是每类 5 张时，能少反传几层而不掉点；远域是否需要更深的适配。先验来自 TinyTrain 表 6，它预测 Aircraft 上 T4 掉 10.6 个点、只训分类头掉 17.6 个点。
- **做什么**：
  - 学习率 pilot：Flowers 18 次，Aircraft 9 次。冻结学习率后，主实验如下：
    - Flowers：{LB, T3, T4, last} × 种子 0–9，T2 × 种子 0–4；
    - Aircraft：{LB, T2, T3, T4} × 种子 0–5，last × 种子 0–4。
  - 假设 H1-F 和 H1-A：在 2 个点的边界上，T3、T4、last 对 LB 做 Holm 校正；T2 是探索性的。

| | LB test | T2 | T3 | T4 | last |
|---|---|---|---|---|---|
| Flowers d | 85.03 | +0.33（探索） | +0.43 retains | −0.03 retains | −6.14 inferior |
| Aircraft d | 25.74 | −0.28（探索） | −0.21 retains | −0.32 retains | −3.94 inferior |

- **结论**：
  - k=5 时，两个数据集上 T4 都不掉点。T4 内存 105 MiB，是 LB 的 1/5.3，计算量是 LB 的 0.61。
  - 只训分类头会掉 4–6 个点。
  - Aircraft 上 TinyTrain 表 6 的先验（T4 −10.6）完全没有出现。可能原因是我们用的是 TinyTL 自己预训练好的 lite residual，而 TinyTrain 用的是新初始化的 adapter；两边协议还有其它差别，包括元学习预训练的主干、样本数、迭代次数和 batch 100。

### E2 改变每类样本数 k

- **目的**：对应故事 ⑧"系统地改变每类样本数 k"，这是"不同数据量下怎样配置"的主轴。
- **做什么**：
  - **K2**：k=2，{LB, T3, T4, last} × 种子 0–4 × 两个数据集。
  - **K10**：k=10，{LB, T4, last} × 种子 0–4 × 两个数据集。
  - **K10-T3、K10-T2**：都是看到结果后追加的，只在 Aircraft 上跑，探索性，不进 Holm。
  - **S（步数对齐对照）**：k=2 固定 50 轮时，训练步数只有 k=5 的 40%。所以种子 0 再跑 125 轮，看结果是否受训练预算限制。
- **结果**（d = arm − LB；R_T4 是 T4 的保留率）：

| | k=2 | k=5 | k=10 |
|---|---|---|---|
| Flowers LB | 68.1 | 85.0 | 92.0 |
| Flowers T4 | +0.82 retains | −0.03 retains | −0.41 retains |
| Flowers last | −4.54 | −6.14 | −5.85 |
| Aircraft LB | 13.9 | 25.7 | 39.5 |
| Aircraft T4 | +0.48 retains | −0.32 retains | −3.35 inferior（R 67%） |
| Aircraft T3 | +0.41 retains | −0.21 retains | −1.55 [−2.58, −0.51] size unresolved（探索，R 85%） |
| Aircraft T2 | — | −0.28（探索） | −1.40 [−2.28, −0.52] size unresolved（探索，R 86%） |
| Aircraft S16-21（119 MiB，见 E3 的 N4） | — | — | −2.15 [−2.72, −1.58] size unresolved（探索，R 79%） |
| Aircraft LB batch 1（122 MiB，见 E5） | — | −1.04 | +0.07 [−2.25, +2.39]（探索，R 101%） |
| Aircraft last | +0.16 retains | −3.94 | −10.27 |

- **S 块**：只有一个种子，只能算迹象。
  - 步数对齐后 val 的提升：Flowers T4 +2.45、LB +1.37，Aircraft T4 +1.50。
  - 所以 k=2 的结果标注为"在 50 轮预算下"。
- **结论**：
  - Flowers 上，k=2 到 10 用 T4 都够。
  - Aircraft 上，数据越多，需要反传得越深：
    - k=2 时只训分类头就和 LB 打平（大家都只有 14% 左右）；
    - k=5 时 T4 就够；
    - k=10 时 T4 掉 3.35 个点；T3 和 T2 都只掉 1.4–1.6 个点，两者打平（T2 只多 0.15 个点，内存却多 58 MiB）。剩下约 1.4 个点要靠训练 stage 1（block 1–8）才能补回，也就是只有训练全部层的 LB 能做到。LB 用 batch 1 只要 122 MiB，平均也做到了（+0.07，见 E5）。按 block 截断到 block 16（119 MiB）比 T4 多补回 1.2 个点（−2.15，见 E3 的 N4）。

### E3 按任务选层（Fisher 选截断点和 block 集合）

- **目的**：对应故事 ⑦"按任务选择适配哪些 block"。问题是训练前用少量样本估计每部分的重要性，能不能比固定规则选得更好。
- **做什么**：
  - k=5，两个数据集，种子 0–4，不需要训练。
  - 用 TinyTrain 的 Fisher potential（Eq. 2/3）给三个组打分：G2 = stage 2，G3 = stage 3，G45 = stage 4–5。打分按可训练参数数和反向计算量归一化。
  - 在 128 MiB 和 256 MiB 预算下，按 TinyTrain 的前缀贪心规则选截断点。
  - 和 oracle 比 regret。oracle 是每个种子实际训练结果最好的 arm。再和两条固定规则比：能放下的最深截断、永远只训分类头。
- **结果**：

| 预算 | Fisher 前缀贪心 | 能放下的最深截断 | 只训分类头 |
|---|---|---|---|
| Flowers 128 MiB | 每个种子都选 last，regret 5.90 | T4，regret 0 | regret 5.90 |
| Aircraft 128 MiB | 每个种子都选 last，regret 3.44 | T4，regret 0 | regret 3.44 |
| 256 MiB（两个数据集） | 都选 T2，和最深截断完全一样（由规则本身决定） | T2，regret 0.07 / 0.25 | |

- 128 MiB 下 Fisher 选 last 的原因：归一化后得分最高的是最前面的 G2，但 G2 那一组放不下 128 MiB，前缀规则只能退回只训分类头。
- 在所有 k、数据集和预算下，选层可提升空间都不超过 0.25 个点。也就是说，即使有完美的按任务选择，在这三个截断点之间也多拿不到什么。
- **结论**：预先登记的判读是"没有优势"。这里只在三个截断点之间选；故事里"只在重要的 block 上训练 lite residual"（不连续的 block 集合）由下面的 N4 来做。

#### N4：按 block 选（看到上面的结果后追加，探索性，不进 Holm）

- **先测内存**：
  - 在 TinyTL 里，梯度要从最后一层一路穿到最早训练的那个 block，路径上每个 GN 和卷积的输入都得保存。
  - 所以训练内存基本由最早训练的 block 决定：只训某一个 block，比从它往后全训只省 2–10%。
  - 128 MiB 下，最深的连续截断是 block 16–21（记作 C，119.2 MiB）；跳过一些 block，就能够到 block 15。
- **做什么**：
  - 选择规则照 TinyTrain：Fisher potential 按参数数和内存归一化打分（Eq. 2/3），从高到低逐个加 block，每个集合都实测内存，超过 128 MiB 就跳过。选择用 `blockselect.py` 在训练前写定。
  - 两个格子：Aircraft k=10（T4 掉点最多的地方）和 Flowers k=5，种子 0–4。
  - 选中的集合（记作 FS）用随机初始化和 imprinting 各跑一次，C 用随机初始化跑，共 30 次。和同种子的 T4、LB、T4 + imprinting 配对。
  - 判定：主读数是 FS − T4（都在 128 MiB 以内），打平判给 T4；FS − C 打平判给 C；C − T4 只作描述。
- **选择结果**：
  - 两个格子的 10 个种子选中的都是同一组：block 15、16、17、19（S15-17_19，127.1 MiB）。
  - 两个数据集的 Fisher 排名有差别，但选出的集合一样。所以选择实际上不随任务变，由内存预算和归一化决定。
  - 归一化让前面参数少的 block 得分高，FS 为了够到 block 15，放弃了最后的 block 18、20、21。
- **结果**（test，种子 0–4 配对）：

| | Aircraft k=10 | Flowers k=5 |
|---|---|---|
| T4（105.2 MiB） | 36.12 | 84.64 |
| C = S16-21（119.2 MiB） | 37.32 | 85.18 |
| FS = S15-17_19（127.1 MiB） | 36.18 | 83.48 |
| **FS − T4（主读数）** | +0.06 [−0.41, +0.53]，打平，判给 T4 | −1.15 [−1.38, −0.93]，固定截断更好 |
| FS − C | −1.15 [−1.86, −0.43]，连续截断更好 | −1.69 [−2.22, −1.17]，连续截断更好 |
| C − T4（描述） | +1.21 [+0.89, +1.53] | +0.54 [+0.08, +1.00] |
| 对 LB：FS / C | −3.29 inferior / −2.15 size unresolved | −1.35 retains / +0.35 retains |
| 保留率 R：T4 / FS / C | 67% / 68% / 79% | 97% / 78% / 106% |
| FS：imprinting − 随机初始化 | −0.01（±1 以内） | +0.83 [+0.24, +1.42] 有帮助 |
| FS + imprinting − T4 + imprinting | −0.26 [−1.20, +0.67]，打平，判给 T4 | −1.09 [−1.40, −0.78]，固定截断更好 |
| 训练计算量（LB = 1）：T4 / C / FS | 0.61 / 0.64 / 0.66 | 同左 |

- **补充描述**（不是事先定的比较）：
  - Aircraft k=10：
    - C 和 169 MiB 的 T3 打平（T3 − C +0.60 [−0.46, +1.66]）；
    - C 比 T4 + imprinting 高 0.89 [+0.09, +1.69]；
    - C 和 LB-b1 打平（LB-b1 − C +2.21 [−0.55, +4.97]，区间宽是因为 LB-b1 波动大）；C 一次训练 12 分钟，LB-b1 要 64 分钟。
  - Flowers k=5：C 是 128 MiB 以内最好的随机初始化配置，但 105 MiB 的 T4 + imprinting 和它打平（+0.22 [−0.16, +0.60]）。
- **结论**：
  - 按 Fisher 选不连续的 block 没有好处：对 T4 一处打平、一处低 1.15 个点，加 imprinting 后也一样；同预算内还输给连续截断 1.2–1.7 个点。
  - 可能的原因：选择被内存规则和归一化主导，选出的集合放弃了最后几个 block，而它们对适配更重要。Aircraft 上 FS 的训练精度 95.3%，低于 T4 的 97.4%，说明它拟合得更少。
  - 真正有用的是截断粒度：同样在 128 MiB 以内，按 block 截断（C，block 16–21）比按 stage 截断（T4，block 17–21）多用 14 MiB，Aircraft 高 1.21 个点，Flowers 高 0.54 个点。这是看到结果后的描述性比较，要靠 N7 复查。
  - 和上面的截断点实验合起来看：在 TinyTL 里按任务选层的空间很小；能放下多深就反传多深，比按任务挑 block 更可靠。

### E4 imprinting 初始化分类头

- **目的**：对应故事 ⑦ 第二点。没有元学习时，用类均值初始化分类头，能不能作为低成本补偿：最终精度能不能更高，能不能用更少的训练达到同样精度。
- **做什么**：
  - **分类头**：最近类均值头，W = 2μ/τ，b = −‖μ‖²/τ。温度 τ 取带标签平滑的训练损失的最小点。
  - **I 块**：T4、last 用 imprinting 初始化 × k ∈ {2, 5} × 种子 0–4 × 两个数据集，和同种子的随机初始化配对。
  - **I10 块**：k=5 时 T4 只训练 10 轮，分别用随机初始化和 imprinting，再和训练 50 轮的 LB 比。
  - **I-LB、I-K10 块**（N1，看到 I 的结果后追加，探索性）：LB 用 imprinting，k ∈ {2, 5}；T4 用 imprinting，k=10。两个数据集，种子 0–4，和 K2、k=5 主实验、K10 里同种子的随机初始化运行配对。
- **结果一：imprinting 本身的效果**（e = imprinting − 随机初始化，50 轮，同一 arm 同一种子配对）：

| | Flowers | Aircraft |
|---|---|---|
| 训练前 imprinting 头的 val（随机头 0.8%） | k=2 58.6%，k=5 73.1%，k=10 79.0% | k=2 11.0%，k=5 15.8%，k=10 18.8% |
| LB，k=2（探索） | +2.85 [+2.05, +3.66] 有帮助 | +1.25 [+0.13, +2.36] 有帮助 |
| T4，k=2 | +1.46 有帮助 | +1.12 有帮助 |
| last，k=2 | +1.34 有帮助 | +0.07（±1 以内） |
| LB，k=5（探索） | +0.99 [+0.56, +1.43] 有帮助 | +0.50 [−0.07, +1.07] 不确定 |
| T4，k=5 | +0.76 有帮助 | +0.56 有帮助 |
| last，k=5 | +0.40 有帮助 | +0.10（±1 以内） |
| T4，k=10（探索） | −0.09 [−0.31, +0.12]（±1 以内） | +0.32 [−0.23, +0.86]（±1 以内） |
| T4，k=5，只训 10 轮 | +1.97 | +2.94 |

- **结果二：加了 imprinting 之后，T4 和 LB 比**（探索，不进 Holm）：

| | Flowers | Aircraft |
|---|---|---|
| k=2：T4-imprinting − LB-imprinting | −0.58 [−1.53, +0.38] retains | +0.35 [+0.04, +0.66] retains |
| k=5：T4-imprinting − LB-imprinting | −0.42 [−0.61, −0.23] retains | −0.44 [−1.16, +0.28] retains |
| k=10：T4-imprinting − LB（LB 没有 imprinting） | −0.50 [−0.88, −0.12] retains（不加时 −0.41） | −3.04 [−3.37, −2.70] inferior（不加时 −3.35） |
| k=5：T4-imprinting 训练 10 轮 − LB 训练 50 轮 | −0.92 retains（计算量 0.12×） | −2.42 size unresolved |

- **结论**：
  - imprinting 几乎没有成本（只多一次前向），而且和截断深度无关：LB 也受益，k=2 时 LB 受益还更多（Flowers +2.85，T4 +1.46）。
  - 好处随 k 增大而消失：LB 和 T4 在 k=2 时 +1.1～+2.9 个点，k=5 时 +0.5～+1.0；k=10 时（只做了 T4）两个数据集都在 ±1 以内。训练前 imprinting 头的精度随 k 上升，但随机头训练 50 轮后也追上来了。
  - 两边都加 imprinting 后，T4 对 LB 的结论不变：k=2、5 时都在 2 个点边界内（−0.58 到 +0.35）。Flowers k=5 有一个显著但很小的差距（−0.42），因为 imprinting 对 LB 帮得稍多。
  - imprinting 补不回 Aircraft k=10 的掉点：T4 + imprinting 仍比 LB 低 3.04 个点，R 只从 67% 升到 70%。远域、数据多时缺的是特征适配的深度，不是分类头的初始化。
  - 训练越短，帮助越大：Flowers 上 T4 + imprinting 训练 10 轮，计算量只有 LB 的 1/8，也不掉点。
  - Aircraft 上只训分类头时，imprinting 的帮助会被训练冲掉。

### E5 batch 大小

- **目的**：对应故事 ⑤⑥。TinyTrain 说 TinyTL 在小 batch 下精度会崩，TinyTL 原论文说用 GN 后 batch 1 几乎不掉点，要澄清这个矛盾。同时问：要放进 128 MiB，减小 batch 和截断哪个好。
- **做什么**：
  - **k=5**（预先登记）：Aircraft，LB 用 batch 1（发布的学习率 3e-4），种子 0–4。
  - **K10-B1**（N2，看到 K10 的结果后追加，探索性，不进 Holm）：Aircraft k=10，设置相同，和 K10、K10-T3 里同种子的 LB-b8、T4-b8、T3-b8 配对。选这里是因为 Aircraft k=10 是唯一截断不够用的地方。
  - H2：对 LB-b8 判断会不会崩，标准是会不会掉 5 个点。
  - H2b：在 128 MiB 以内，对 T4-b8 比较；打平判给 T4，因为它内存更少、计算更少。
- **结果**（d = LB-b1 − 对照，batch 8）：

| | k=5（预先登记） | k=10（探索） |
|---|---|---|
| H2：对 LB-b8 | −1.04 [−3.31, +1.22]，不崩 | +0.07 [−2.25, +2.39]，不崩 |
| 5 个种子 | −4.4 / +0.1 / −1.4 / −0.4 / +0.9 | +1.9 / +0.8 / −3.5 / +1.1 / +0.0 |
| H2b：对 T4-b8（105 MiB） | −0.55 [−2.91, +1.81]，打平，判给 T4 | +3.42 [+0.84, +6.00]，batch 更好 |
| 对 T3-b8（169 MiB，只作描述） | — | +1.61 [−0.68, +3.90]，打平 |
| 一次运行的时间：LB-b1 / T4-b8 | 34 / 8 分钟 | 64 / 12 分钟 |

  - 两次都没能证明掉点在 2 个点以内：batch 1 的种子间波动明显比 batch 8 大。k=10 时 test 的标准差是 2.5 对 0.6，种子 2 掉了 3.5 个点。
  - 学习率检查两次都没用上：k=5 掉点没超过 2 个点，条件 2 没触发；k=10 平均没有掉点。
  - **速度**：在空闲 GPU 上，batch 1 每一步和 batch 8 一样慢，所以每张图慢 13 倍。按一次运行的实际耗时算，LB-b1 是 T4-b8 的 4–5 倍。
- **结论**：
  - 在 TinyTL 自己的 GN 配置下，batch 1 在 k=5 和 k=10 都不崩，TinyTrain 的说法不成立；成因可能在于 TinyTrain 的实现不同。
  - 同样 128 MiB 以内，batch 1 和截断哪个好，取决于截断掉不掉点：
    - k=5 时 T4 不掉点，batch 1 没有好处，而且更慢；
    - k=10 时 T4 掉 3.35 个点，LB-b1 比它高 3.42 个点，平均和 LB-b8 一样，也追平了 169 MiB 的 T3。
  - 所以默认用 batch 8，靠截断省内存。只有截断不够用（远域、k=10），内存又卡在 128 MiB 时，才换成 LB + batch 1，代价是训练慢约 5 倍、结果随种子波动更大。
  - N4 之后多了一个选择：按 block 截断的 S16-21（119 MiB，batch 8）。它平均比 LB-b1 低约 2 个点（区间跨 0），但快 5 倍、更稳（见 E3 的 N4）。

### E6 稳健性检查

| 检查 | 做什么 | 结果 |
|---|---|---|
| 学习率在网格下沿（Q3，X 块） | Aircraft 上 LB 和 T3 选中的 4e-4 在原网格的最低一档，再试 1e-4 和 2e-4 | LB：23.1 / 25.0 / 26.4；T3：23.4 / 24.9 / 26.6。4e-4 仍然最好，不换学习率 |
| 50 轮预算够不够（半程检查） | 第 45–50 轮的 val 比第 20–25 轮高 1.5 个点以上，就加跑一次 100 轮 | Flowers 没触发。Aircraft 的 last 触发，100 轮只多 0.30 个点，不加标注 |
| 只测最后一轮的影响（协议桥） | 旧 r2 运行的"最佳 val"和"最后一轮"两个 checkpoint 各在 test 上测一次 | 最后一轮平均反而高 0.35 个点，测最后一轮不吃亏 |
| H2 学习率检查（条件 2） | batch 1 掉点超过 2 个点时，换学习率重跑 | 没触发。k=10 的 K10-B1 没有设这一步，它平均也没有掉点 |

## 四、目前的配置建议

| 近域，计算也紧 | T4 + imprinting，只训 10 轮 | 105 MiB，计算量 0.12× | 对 LB 训练 50 轮 −0.92，retains（探索性） |
| 远域（Aircraft），k=2 | last 就够；有 105 MiB 时用 T4 + imprinting | 67 / 105 MiB | 所有 arm 和 LB 打平；imprinting 对 T4 +1.12，T4 + imprinting 比 LB + imprinting 还高 0.35 |
| 远域，k=5 | T4，batch 8，imprinting | 105 MiB | T4 不掉点；imprinting +0.56；两边都加 imprinting 后 T4 对 LB −0.44，retains |
| 远域，k=10 | 内存 ≤ 128 MiB：LB + batch 1（平均最高）或 S16-21 + batch 8（快、稳）；内存够、要快：T3 或 S16-21，batch 8（两者打平，再往深到 T2 没有好处）；内存不限：LB，batch 8 | 122 / 119 / 169 / 557 MiB | LB-b1 对 LB-b8 +0.07 [−2.25, +2.39]，对 T4-b8 +3.42；但每次训练 64 分钟，种子间波动大。S16-21 对 LB −2.15，比 T4 高 1.21、比 T4 + imprinting 高 0.89，和 T3（差 0.60）、LB-b1（差 2.21，区间宽）都打平，每次 12 分钟。batch 8 时 T4 −3.35，T3 −1.55，T2 −1.40；imprinting 补不回（T4 + imprinting 仍 −3.04）；Fisher 选 block 也不行（−3.29）。都是探索性的 |
| 内存不受限，k ≤ 5 | LB + imprinting 或 T4 + imprinting | 557 / 105 MiB | 两者差距都在 0.6 个点以内（Flowers 上 LB 略高，Aircraft k=2 时 T4 略高；探索性），T4 省 5 倍内存 |
| 内存不到 105 MiB | 只训分类头 | 67 MiB | Flowers 掉 4.5–6 个点；Aircraft 在 k=2 时不掉，k=5 掉 3.9 个点，k=10 掉 10.3 个点 |
| batch | 默认 batch 8；只有截断掉点、内存又卡在 128 MiB 时用 LB + batch 1 | | batch 1 不崩（Aircraft k=5、10）。k=5 时不比截断好；k=10 时比 T4 高 3.42 个点。每张图慢 13 倍，每次运行的耗时是 T4-b8 的 4–5 倍 |
| 选哪些层 | 在预算内取能放下的最深连续截断，按 block 而不是按 stage 算；不用 Fisher 挑不连续的 block | | 在截断点之间按任务选，最多只能多拿 0.25 个点（E3）；Fisher 选的 block 不比 T4 好，比同预算的连续截断低 1.2–1.7 个点（N4）；S16-21 比 T4 多 14 MiB，高 0.5–1.2 个点（描述性，待 N7 复查） |

规律：越远域、数据越多，越需要往深处反传；数据越少，imprinting 帮助越大，到 k=10 已经没有帮助。imprinting 是不分 arm 的免费小增益，但代替不了反传深度。截断不够用时，batch 1 能用 122 MiB 换回完整的反传深度，代价是时间。按任务挑 block 没有好处；同样的内存，按 block 粒度取能放下的最深连续截断更好。

N4 的教训：在 TinyTL 里，从最早一个训练的 block 往后，梯度都要穿过，所以跳过中间的 block 主要省计算，换不来多少内存（只省 2–10%）。按 Fisher 挑 block 在相同内存下也没有好处，剩下值得做的是 N7：把截断的粒度从 stage 细化到 block。

## 七、已知局限

- 只用了一个主干（ProxylessNAS-Mobile）、一个分辨率（224 px）和两个数据集。
- 各个 k 没有单独调学习率，沿用 k=5 的学习率；imprinting 运行也沿用为随机初始化调好的学习率。
- k=2 受 50 轮训练预算限制（S 块，单种子迹象）。
- 补充实验每个配置只有 5 个种子。K10-T3、K10-T2、I-LB、I-K10、K10-B1、N4 是看到结果后追加的，只算探索性结果。
- N4 在所有种子和两个数据集上选中的都是同一组 block，所以它实际比较的是一个固定的不连续集合，没有检验到"因任务而异"的选择。block 集合 arm 沿用 T4 的学习率，没有单独调。按上游规则，冻结的 block 会做 8-bit 量化，FS 里不训练的 block 18、20、21 也被量化了，所以比较的是整套配方。
- batch 1 的学习率用的是上游发布值 3e-4，没有为 k=10 重新调。batch 1 的种子间波动比 batch 8 大，5 个种子下区间较宽。
- 内存是 PyTorch fp32 的实测值，不包括重计算、低精度激活等进一步省内存的手段。
- 训练时间只代表我们这台 RTX 3060。
