# 反传深度实验：运行说明

对应 `最终实验设计.md` 和 `补充实验设计.md`。所有命令都在 `outputs/TinyTL` 目录下的 Git Bash 里运行。现有文件和上游代码都没有改，需要改上游行为的地方只在我们自己的脚本里打补丁。

## 文件

| 文件 | 作用 |
|---|---|
| `depth_common.py` | 共用部分：网络构建；每种截断方式训练哪些参数（`set_trainable`）；可训练参数数的期望值；运行目录命名；带缓存、可复现的 8-bit 量化（`quantize_frozen`） |
| `fewshot_depth.py` | 单次训练：每类抽 k 张，训练 50 轮，直接用最后一轮的模型测一次 test，结果写进 `runs/<名字>/result.json` |
| `measure_memory.py` | 三种口径的内存：profiler、理想实现下限、PyTorch 实测。实测用 3 个进程、3 种顺序，另用一个进程算前两种口径；结果写进 `memory_table.json` |
| `make_runlist.py` | 生成运行列表，以及冻结学习率的 `freeze` 步骤 |
| `run-depth-sweep.sh` | 按运行列表逐个跑：已完成的跳过，遇到失败或格式不对的行就停 |
| `run-flowers.sh`、`run-aircraft.sh` | 一个数据集的全部流程：pilot → 冻结学习率 → 半程检查 → 主实验（Aircraft 还有 batch-1 和条件 2） |
| `prepare_aircraft.py` | Aircraft 解压、裁掉底部版权条、缩放到短边 512，以及 k-shot 抽样函数 |
| `analyze_depth.py` | 按预先登记的规则出结果：H1 标签与 Holm、H2/H2b、条件 2、半程检查、跨数据集对比。最后附一段事后补充指标（非预先登记，对应故事 PDF 的目的）：适配收益保留率 R、训练−测试差距、各内存预算下的最好配置、选层可提升空间 |
| `measure_macs.py` | 每个 arm 每张图的前向/反向 MACs（只用 CPU），写进 `macs_table.json` |
| `measure_time.py` | 每个 arm 在 batch 8 和 1 下每步的 GPU 时间，写进 `time_table.json`；GPU 不空闲就拒绝运行 |
| `fisher_stage.py` | H4：训练前用 Fisher 在内存预算下选截断点，和 oracle 及两条固定规则比较，写进 `fisher_table.json` |
| `eval_final_ckpt.py` | 协议桥：旧 r2 运行的"最佳 val"和"最后一轮"两个 checkpoint 在 test 上各测一次，写进 `bridge_result.json` |

## 截断方式（arm）

所有 arm 前向时都保留全部 lite residual，区别只在哪些参数接收梯度，以及哪些冻结层做了 8-bit 量化（这和上游一致）。

| arm | 训练的参数 | 可训练参数（102 类） |
|---|---|---|
| `LB` | 完整 TinyTL-L+B，参数集合与上游完全相同 | 1,962,310 |
| `T2` | 从 block 9 开始（stage 2–5）的 bias 和 lite residual，加分类头 | 1,863,766 |
| `T3` | 从 block 13 开始（stage 3–5） | 1,578,246 |
| `T4` | 从 block 17 开始（stage 4–5） | 1,113,126 |
| `last` | 只有分类头 | 130,662 |

每次运行开始前都会检查可训练参数数是否和上表一致，不一致就直接报错。

## 步骤

1. **Smoke test**：`.venv/Scripts/python.exe make_runlist.py smoke`，然后 `bash run-depth-sweep.sh runlists/smoke.csv`
2. **内存表**：`.venv/Scripts/python.exe measure_memory.py`
3. **学习率 pilot**（18 次运行，白天跑）：`.venv/Scripts/python.exe make_runlist.py pilot`，然后 `bash run-depth-sweep.sh runlists/pilot_flowers102.csv`
4. **冻结学习率**：`.venv/Scripts/python.exe make_runlist.py freeze`
   - 生成 `lr_choice_flowers102.json`。之后它就不再改，再运行这一步会被拒绝。
   - 同时做半程收敛检查。如果检查触发，会生成 `runlists/halfbudget_flowers102.csv`，这一次 100 轮的运行也要跑。
   - 发散（loss 变成 nan）的学习率按最差处理。
5. **主实验 A-F**（45 次运行，晚上跑）：`.venv/Scripts/python.exe make_runlist.py main`，然后 `bash run-depth-sweep.sh runlists/main_flowers102.csv`

预先登记的削减方案：`main --n_seeds 9`；`pilot --drop_lr 3.2e-3`，同时 `freeze` 也要加 `--drop_lr 3.2e-3`。

## 跑之前

- 关掉其它占用 GPU 的程序。每次 sweep 开始时，GPU 利用率会写进 `depth-sweep.log`。
- 关闭系统睡眠：在 PowerShell 里运行 `powercfg /change standby-timeout-ac 0`。
- 中断后直接重跑同一条命令：已完成的会跳过，没跑完的那一次会自己清空后重来。
- 同一时间只能跑一个 sweep，`runs/.sweep.lock` 就是用来防止同时跑的。如果机器崩溃后这个锁目录还留着，手动删掉即可。

## 需要知道的几点

- **量化可复现。** sklearn 的 KMeans 在多线程下即使固定随机种子，结果也不完全一致。所以改成单线程量化，并按层缓存到 `cache/quant8_rs0.pth`。同一层不管出现在哪个 arm、哪个种子里，量化结果都逐位相同；第一次之后也不用再算。
- **配对的含义。** 同一个种子下，各 arm 的训练图、分类头初始化、量化权重、数据顺序和数据增强都相同。这些都记在 `result.json` 的 `subset_sha1`、`head_init_sha1`、`frozen_sha1` 里，分析时可以逐对检查。GPU 上的数值计算不是逐位可复现的（cudnn.benchmark，以及 GN 和双线性上采样反向用到的原子操作），这属于噪声，不是偏差。
- **顺序和设计不同。** 设计里是先跑 Aircraft，这样 H2 学习率复查的决定能落在两个晚上之间。现在按要求先跑 Flowers。Flowers 的实验不依赖 Aircraft 的结果，所以只是 Aircraft 那边会多占一个晚上。
- **`B`（TinyTL-B）只出现在内存表里。** 它比上游的 tinytl-bias 少训练 19 个 `final_bn` bias（共 2,016 个参数）。

## GPU 空闲后再跑

Aircraft 整条流程（`run-aircraft.sh`）跑完、`runs/.sweep.lock` 消失之后，按顺序运行。`measure_time.py` 在 GPU 利用率超过 5% 或 sweep 还在跑时会直接拒绝；另外两个在 sweep 还在跑时也会拒绝，除非加 `--allow_busy`。

| 命令 | 大约耗时 | 输出 |
|---|---|---|
| `.venv/Scripts/python.exe measure_time.py` | 5 分钟 | `time_table.json`，只代表我们这台机器 |
| `.venv/Scripts/python.exe fisher_stage.py` | 几分钟 | `fisher_table.json` |
| `.venv/Scripts/python.exe eval_final_ckpt.py` | 3 分钟 | `bridge_result.json` |

`measure_macs.py` 只用 CPU，已经跑过（`macs_table.json`）；它会检查结果和设计里的数字（`过程/macs_result.json`）一致。

检查用的命令（只用 CPU，不碰 GPU）：`fisher_stage.py --smoke`、`eval_final_ckpt.py --check`。

## 补充实验（`补充实验设计.md`）

一条命令跑完：`bash run-supp.sh`（约 14 GPU 小时；学习率检查若触发重跑，最多再加 3.4 小时）。中断后重跑同一条命令即可续跑。

| 文件 | 作用 |
|---|---|
| `run-supp.sh` | 整条流程：块 X（Aircraft 低学习率）→ `lrx_freeze` → 条件重跑 X-R → `runlists/supp.csv`（K2、S、I、K10、I10）→ `analyze_supp.py` → GPU 空闲时顺带跑 `measure_time.py` |
| `make_runlist.py lrx / lrx_freeze / supp / smoke_supp` | 生成补充实验的运行列表；`lrx_freeze` 写 `lr_choice_aircraft_supp.json`，写定后不再改 |
| `fewshot_depth.py --head_init imprint` | 训练前把分类头换成最近类均值头（温度取带标签平滑的训练损失在 k 张图上的最小点；留一法只作诊断记录） |
| `analyze_supp.py` | 按补充设计里写定的规则出结果，写进 `实验设计/分析输出_补充.txt` |
| `make_runlist.py k10t3` | 追加块 K10-T3：Aircraft k=10 的 T3，种子 0–4，写 `runlists/k10t3_aircraft.csv`。跑法：`bash run-depth-sweep.sh runlists/k10t3_aircraft.csv`，再重跑 `analyze_supp.py` |

运行列表多了一列 `head_init`；`run-depth-sweep.sh` 同时接受旧的 11 列和新的 12 列列表。新运行的名字只在 imprinting 时多一个 `-imp` 后缀，旧运行的名字不变。

检查用的命令：`make_runlist.py smoke_supp` 后 `bash run-depth-sweep.sh runlists/smoke_supp.csv`（4 次 1 轮的运行，覆盖 k=10、k=2、imprinting 两个数据集）。

## H4 需要知道的两点

- **256 MiB 下预先登记的规则没有区分度。** 所有候选截断都放得下 256 MiB（最深的 T2 是 226.5 MiB），而一组前缀的内存由其中最早的那一组决定，所以前缀贪心总会把三组全选上，结果永远是 T2，和"能放下的最深截断"这条固定规则完全一样，与 Fisher 分数无关。只有 128 MiB 有区分度：G45 排第一就选 T4，否则选 FT-Last。脚本旁边另外给出一条 `top1` 规则（能单独放下的最高分组），明确标为"未预先登记"。
- **分类头在完整类别集上没有饱和。** smoke test 只取 20 类时，支持集几乎全部分对，Fisher 主要来自少数几张图。在完整的 102 / 100 类上，留一法原型头在 seed 0 的支持集准确率是 67.6%（Flowers）和 15.8%（Aircraft），梯度不会消失。每个种子都会记录支持集 loss、准确率，以及前 10 张图占 Fisher 总量的比例。
